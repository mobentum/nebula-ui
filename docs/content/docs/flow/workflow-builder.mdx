Each example is just `nodes` and `edges` data — connect them like any React Flow graph:

```tsx
const nodes = [
  { id: 't1', type: 'trigger', position: { x: 0, y: 80 }, data: { title: 'Video published' } },
  { id: 'a1', type: 'agent', position: { x: 280, y: 80 }, data: { title: 'Transcriber' } },
  { id: 'k1', type: 'task', position: { x: 560, y: 0 }, data: { title: 'Write blog post' } },
  { id: 'k2', type: 'task', position: { x: 560, y: 80 }, data: { title: 'Generate clips' } },
];

const edges = [
  { id: 'e1', source: 't1', target: 'a1' },
  { id: 'e2', source: 'a1', target: 'k1' },
  { id: 'e3', source: 'a1', target: 'k2' },
];
```

## Node palette

`NodePalette` renders a list of draggable items. Each item sets `application/reactflow` with its node `type` on drag start:

```tsx
import { NodePalette, useNodeDrop } from '@mobentum/nebula-flow';

const items = [
  { type: 'trigger', label: 'Trigger', description: 'Inbound event' },
  { type: 'agent', label: 'Agent', description: 'Model + persona' },
];

function Canvas() {
  const { onDrop, onDragOver } = useNodeDrop({ onAddNode: addNode });

  return (
    <div className="h-[440px] w-full">
      <Flow
        nodes={nodes}
        edges={edges}
        onNodesChange={onNodesChange}
        onEdgesChange={onEdgesChange}
        onConnect={onConnect}
        onDrop={onDrop}
        onDragOver={onDragOver}
        className="h-full w-full"
      />
    </div>
  );
}
```

`useNodeDrop` reads the dropped type, converts the pointer position with `screenToFlowPosition`, and calls `onAddNode` (typically `addNode` from `useFlowGraph`). Use it inside `FlowProvider`.

## Connection validation

Pass `rules` to `Flow` to restrict which nodes can connect. A rule matches a source → target node-type pair; `'*'` matches anything. `preventCycles` is on by default.

```tsx
import { Flow, createFlowRules } from '@mobentum/nebula-flow';

const rules = [
  { source: 'trigger', target: 'agent' },
  { source: 'agent', target: 'task' },
  { source: 'task', target: 'condition' },
];

<Flow nodes={nodes} edges={edges} rules={rules} className="h-[400px]" />;
```

`rules` also accepts a full validator from `createFlowRules` (e.g. with `preventCycles: false`), and any custom `isValidConnection` is combined with the rules.

## Undo / redo

Enable `history` on `useFlowGraph` to get `undo`, `redo`, `canUndo`, and `canRedo`. Structural changes (connect, add, remove, update, layout) are undoable; node drags are grouped per gesture.

```tsx
const graph = useFlowGraph({ initialNodes, initialEdges, history: true });
// graph.undo(), graph.redo(), graph.canUndo, graph.canRedo
```

## Auto-layout

`layoutFlow` arranges a DAG into clean layers (dependency-free):

```tsx
import { layoutFlow } from '@mobentum/nebula-flow';

const arranged = layoutFlow(nodes, edges, { direction: 'LR' });
setGraph(arranged, edges);
```

Options: `direction` (`'TB'` default or `'LR'`), `nodeWidth`/`nodeHeight`, and `horizontalSpacing`/`verticalSpacing`.

## Serialization

Persist a flow with `toJSON` / `fromJSON` from `useFlowGraph` (or `serializeFlow` / `deserializeFlow`). The output is a versioned, idempotent schema with computed fields (`positionAbsolute`, `width`, `height`, `selected`, `measured`) stripped — safe to store in your workspace or backend.

```tsx
const json = graph.toJSON();          // { version: 1, nodes, edges }
graph.fromJSON(json);
```
